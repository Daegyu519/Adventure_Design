# R-01 Codex 예상답안과 경쟁 제품 조사

작성·공식 자료 확인: 2026-11-10 · [인터뷰 질문지](R-01-interview-guide.md) · [비교 시나리오](R-01-comparison-scenarios.md)

아래 인터뷰 답변은 Codex가 작성한 가상 사례다. 사람에게서 수집한 응답은 0건이다. 경쟁 제품은 공개된 기능과 사용법을 조사했다. 삼성·Grammarly·OOPS!의 동일 예문 실행 결과와 걸린 시간은 미측정이다. 일반 LLM 예시는 이 작업을 진행한 Codex가 작성했다.

## 1. 가상 인터뷰 14문항

대학생 팀플에서 자료 취합을 맡은 조원을 가정했다. 첫 사례에서는 같은 조 동기와 반말을 쓴다.

| 문항 | Codex 예상답안 | 실제 인터뷰에서 기록할 것 |
|---|---|---|
| 1. 최근 오래 고친 메시지 | 발표 전날 저녁에 자료를 아직 안 올린 동기에게 단톡에서 재촉했어. 다른 조원들도 읽는 방이었고, 자료가 있어야 그날 밤 발표 파일을 합칠 수 있었어. | 가장 최근 사례, 관계, 공개 단톡인지 개인 메시지인지, 왜 그때 보내야 했는지 |
| 2. 고친 횟수와 시간 | 세 번쯤 고쳤고 4분 정도 걸렸어. 처음에는 안 올린 걸 따졌고, 두 번째에는 너무 돌려 말해서 언제까지 필요한지가 빠졌어. | 수정 횟수와 경과 시간의 대략적인 값, 기억이 불확실하면 그대로 표시 |
| 3. 가장 걱정한 점 | 공개적으로 면박 주는 것처럼 읽힐까 걱정했어. 동시에 기한을 빼면 상대가 내일 보내도 된다고 생각할 수 있었어. | 걱정한 해석과 유지해야 했던 요구를 구분 |
| 4. 보낸 뒤 결과 | 발표 준비 때문에 오늘 밤까지 필요하다고 적어서 보냈어. 그날 자료가 올라왔어. 상대가 기분 나빴는지는 물어보지 않았어. | 실제로 관찰한 행동과 발신자의 추측을 구분 |
| 5. 평소 대처 | 이때는 혼자 고쳐 보냈어. 다른 팀플에서 추가 역할을 거절할 때는 AI에 상황을 한 줄로 설명하고 표현을 물어본 적 있어. | 방금 이야기한 사례에서 실제로 한 일과 다른 사례의 대처를 구분 |
| 6. 확인 방법의 장단점 | AI가 표현을 빨리 몇 개 줘서 시작하기 쉬웠어. 동기에게 쓰기엔 문장이 너무 정중하거나 거절이 애매해져서 다시 고쳤어. 친구에게 묻는 건 편하지만 바로 답이 온다는 보장이 없었어. | 도움이 된 결과, 결과를 그대로 썼는지, 다시 고친 부분 |
| 7. 고민 빈도 | 최근 한 달에 세 번쯤. 마감이 겹친 주에 두 번 있었어. 일정이 없는 주에는 거의 없었어. | 최근 한 달의 실제 건수와 마감 주간에 몰리는지 |
| 8. 도움받고 싶은 순간 | 별로 안 친한 조원에게 처음 재촉할 때. 어느 표현이 따지는 말처럼 들릴 수 있는지 짧게 보고, 필요하면 내가 바꾸고 싶어. | 언제 열어 보는지와 원하는 설명의 깊이 |
| 9. 간섭으로 느낄 순간 | 친구와 짧게 답을 주고받거나, 지금 바로 시간만 확인할 때. 이미 두 번 말한 기한을 다시 공지할 때도 매번 뜨면 귀찮을 것 같아. | 도움이 필요 없는 예와 반복 안내를 받아들일 수 있는지 |
| 10. 의도적으로 단호할 때 | 추가로 맡을 수 없다는 뜻은 그대로였으면 좋겠어. 말투를 고르더라도 상대가 협의 가능한 답으로 받아들이면 다시 일이 돌아올 수 있어. | 남겨야 하는 문구·조건과 실제로 허용할 수정 범위 |
| 11. 주 메신저 | 팀플이랑 친구 연락 모두 카카오톡을 써. | 최근 사례에서 사용한 메신저 |
| 12. 쓰는 위치와 설치 | 메신저 쓰는 화면에서 내가 열 수 있으면 좋아. 중요한 메시지라면 앱을 따로 열 수도 있어. 팀원에게 새 앱 설치를 부탁하거나 기본 키보드를 바꿔야 하면 망설여져. | 별도 앱, 키보드 교체, 상대도 가입하는 조건을 각각 질문 |
| 13. 기능 설명 없이 이름 추측 | '상대 입장에서 읽기'는 내가 보낼 문장을 받는 쪽에서 보는 기능 같아. '어떻게 들릴까?'는 말투 점검 같아. '거울 모드'는 뭘 하는지 모르겠어. '대화 연습'은 AI와 대화하는 것 같고, '답장 연습'은 내가 답장을 써보는 것 같아. | 선호를 묻기 전에 이름마다 예상 기능을 자기 말로 설명하게 함 |
| 14. 설명을 들은 뒤 사용 상황 | 마감 당일의 재촉이나 추가 역할 거절처럼 보내기 전에 한 번 멈추는 상황에서 써볼 것 같아. 앞 대화에 따라 같은 말이 왜 다르게 들릴지 바로 보여주면 써볼 이유가 있어. | 구체적인 사용 상황, 기존 방법으로 충분한 이유, 사용을 포기할 조건 |

## 2. 경쟁 제품 공식 자료 조사

| 비교 대상 | 확인된 기능과 입력 | 설치·권한·사용 흐름 | 이 조사에서 남은 질문 |
|---|---|---|---|
| Grammarly 한국어 제안 | 공식 지원 언어에 한국어가 포함된다. 문단 단위 재작성 지원 언어 목록에는 한국어가 없다. 말투 감지와 문장 단위 말투 수정도 별개 기능으로 안내된다. [언어 지원][g-lang] · [말투 기능][g-tone] | Android용 Grammarly는 기존 키보드 위에 위젯을 띄우며, 앱 설치 후 접근성 및 화면 오버레이 권한을 사용한다. [Android 사용법][g-android] · [권한][g-privacy] | 한국어 제안이 테스트할 앱·버전에서 표시되는가? 짧은 한국어 문장에서 말투 진단이나 수정안도 제공하는가? |
| Grammarly Reader Reactions | 글의 독자 유형을 선택하고 독자가 이해할 내용, 가질 질문, 혼란을 느낄 대목에 대한 피드백을 받는다. 공식 도움말은 Docs와 Superhuman Go 경로를 안내하고 Android용 Go 안내에도 기능이 나온다. [Reader Reactions][g-reader] · [Android용 Go][g-go] | Docs에서는 초안 입력 → 에이전트 열기 → 필요하면 독자 선택 → 피드백 확인. Android용 Go는 앱 설정 및 접근성·오버레이 권한이 필요하다. 요금제와 사용 경로를 실행 시 기록한다. [Reader Reactions][g-reader] · [Android용 Go][g-go] | 한국어 반말과 존댓말에서 작동하는가? 같은 독자 유형에 직전 발화만 바꿔 넣었을 때 해석이 달라지는가? |
| 삼성 키보드 글쓰기 어시스트 | 작성한 텍스트에 문장 스타일 변경을 적용한다. 삼성 공식 지원 언어에 한국어가 포함된다. 글 작성과 답장 추천도 별도 기능이므로 문장 스타일 결과와 섞어 평가하지 않는다. [삼성전자서비스][s-kr] · [지원 언어][s-us] | 지원 Galaxy에서 초안 입력 → 글쓰기 어시스트 → 문장 스타일 → 적용. 기종, One UI, 국가·언어, 계정 및 기기 내 처리 설정에 따라 이용 조건을 기록한다. [사용 방법][s-kr] · [Galaxy AI 설정][s-ai] | 카카오톡 입력창에서 실제 동작하는가? 선택한 스타일이 높임말과 기한·거절을 유지하는가? 직전 메시지 변경이 문장 스타일 결과에 영향을 주는가? |
| 일반 LLM | 관계, 직전 발화와 초안을 함께 입력해 해석·수정을 요청하는 비교 경로. [공통 프롬프트](R-01-comparison-scenarios.md) | 비교에서는 메시지 작성 화면과 LLM을 오가며 예문을 입력하고 결과를 다시 옮긴다. 실제 조작 수는 기기에서 센다. | 간단한 질문만으로 의도를 살리는가? 맥락을 옮기는 수고가 사용을 포기할 정도인가? |
| OOPS! | 저장소 설계상 전송 시점에 말투를 확인하고, 경고가 뜨면 수정하거나 그대로 보낼 수 있다. 별도 거울 세션은 카드 기반 연습이다. [아키텍처](../../ARCHITECTURE.md) | 앱의 대화방에서 비교한다. 상대도 방에 들어와 있어야 한다. | 실제 버전에서 S4의 두 상황을 다르게 다루는가? 유용한 경고까지 걸리는 시간과 불필요한 경고 빈도는 얼마인가? |

Reader Reactions가 있어 '상대 입장 피드백 자체가 새롭다'는 근거는 없다. 삼성의 답장 추천이 있다는 사실만으로 문장 스타일 기능이 직전 발화를 읽는다고 판단할 수도 없다. 2021년 Grammarly의 삼성 키보드 통합 발표는 당시 기능을 확인하는 자료다. 현재 비교에서는 Grammarly 제품과 Galaxy AI 글쓰기 어시스트를 각각 실행하고 경로와 버전을 기록한다. [2021년 통합 발표][g-samsung]

## 3. 동일 예문에 대한 Codex 예상답안

비교 문서의 초안과 맥락을 사용했다. 아래 수정안은 검증할 기준을 보여주는 예시다. 일반 LLM을 새 대화에서 기본 프롬프트만으로 평가할 때는 기준표의 '지킬 의도'를 입력에 추가하지 않는다.

| 사례 | Codex가 짚은 해석 | 수정안 또는 판단 | 실측에서 볼 것 |
|---|---|---|---|
| S1. 자료 재촉 | '아직도'는 발표를 준비하는 데 필요한 일정 확인을 넘어, 미제출을 따지는 말로 읽힐 수 있다. | '내일 발표라 자료 오늘 안에 올려줘.' 여기서 '오늘 안에'는 테스트 문서에 적힌 의도를 반영했다. 초안의 '내일 발표인데'는 발표일을 말한다. | 기본 프롬프트에서 기한을 명시하는지 기록한다. 의도를 입력하지 않은 결과가 기한을 빠뜨리면, 입력에 있던 기한을 삭제한 경우와 구분한다. |
| S2. 역할 거절 | '안 될 것 같아요'가 조심스러운 거절로 읽힐 수도 있고, 조장이 다시 부탁할 여지가 있다고 받아들일 수도 있다. | '죄송하지만 이번에는 PPT까지 맡기 어렵습니다.' | 맡지 않는다는 뜻과 존댓말을 유지하는지, '가능한 부분은 돕겠다' 같은 약속을 추가하는지 본다. |
| S3. 답 없는 조원에게 확인 | '답이 없으셔서요'가 상대를 탓하는 느낌을 줄 수 있다. | '단톡에 올린 내용 확인하시고 답장 부탁드려요.' | 읽기만 하라는 뜻으로 흐려지지 않는지, 확인과 답장을 둘 다 요청하는지 본다. |
| S4-A. 상대가 불안을 털어놓음 | 'ㅇㅇ 알아서 해'는 어떤 도움이 필요한지 확인하기 전에 상대를 밀어내는 말로 읽힐 수 있다. | '발표 어떤 부분이 제일 걱정돼?' | 어떤 표현이 직전 발화와 맞물려 문제인지 설명하는지 본다. |
| S4-B. 상대가 자료를 정리하겠다고 제안 | 같은 초안이 일을 맡긴다는 의미로 읽힐 수 있다. '알아서 해'가 무심하게 들릴 여지는 관계에 따라 달라진다. | 기본값은 경고 없이 진행. 더 분명히 확인하려면 '응, 그럼 마저 정리해줘.' | S4-A와 경고 유무 또는 강도가 달라지는지 확인한다. |

실측에서는 합성 예문을 쓰고 도구·기종·버전·언어·요금제·입력한 맥락 범위를 기록한다. 초안 입력 이후부터 결과를 보내기 직전까지 실제로 누른 횟수를 세고, 설치와 최초 권한 설정은 따로 기록한다. S4는 초안을 고정하고 앞 대화만 바꾼다. 두 사례의 답을 볼 수 있게 새 세션이나 새 방으로 분리한다. 실제로 실행했지만 기능을 사용할 수 없었던 경우에는 이유와 경로를 적고, 미실행은 '미측정'으로 둔다.

## 4. R-01 잠정 판단

- **초기 타깃 가설**: 팀플에서 자료를 취합하거나 일정을 조율하는 대학생. 첫 검증 상황은 발표 전날 단톡에서 기한을 지켜 달라고 재촉하는 경우다.
- **제품 설명 초안**: OOPS!는 한국어 팀플에서 메시지를 보내기 전에, 상대가 방금 한 말에 비춰 어떤 표현이 어떻게 읽힐 수 있는지 알려 주고 기한·거절·요청을 유지할 수 있게 돕는다.
- **도움이 필요 없는 상황 가설**: 친한 사이의 짧은 확인, 시간에 민감한 공지, 이미 합의한 기한을 그대로 전달할 때는 빠르게 그대로 보낼 수 있어야 한다.
- **차별화 가설**: 이미 대화방에 있는 직전 맥락을 활용해 복사·붙여넣기 없이 구체적인 설명을 보여주고, 한국어 관계와 높임말을 살리면서 요구를 유지한다. 별도 앱과 팀원의 가입이 주는 부담까지 포함해 비교한다.
- **진행 판단**: 탐색 인터뷰와 동일 예문 실측을 계속한다. 실제 인터뷰에서 반복 사례와 수정 수고가 확인되고, 실측에서 S4를 구분하면서 S1~S3의 의도를 지키면 검증을 이어갈 근거가 된다. 사례가 드물거나 기존 대처로 충분하다는 답이 많으면 더 좁은 상황으로 수정하거나 보류한다.
