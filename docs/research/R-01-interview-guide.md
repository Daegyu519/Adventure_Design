# R-01 인터뷰 질문지

작성: 2026-11-10 · 개정: 2026-11-10(파일럿 응답 반영) · 연결: [feedback-roadmap.md](../feedback-roadmap.md) §1 R-01

한 사람당 **15~20분**. 탐색용이며 시장 규모의 증거로 쓰지 않는다.

진행 연습용 [Codex 예상답안과 경쟁 제품 조사](R-01-codex-expected-answers.md)가 있다. 실제 인터뷰 응답과 따로 관리한다.

## 이번 인터뷰로 확인할 것

파일럿 응답(P0, 아래)에서 **"말투가 차가워 보일까"보다 "이 상황에서 뭐라고 답하지"가 진짜 고민**이라는 가설이 나왔다. 그래서 고민을 세 종류로 나눠 듣는다.

| 종류 | 예 | 지금 제품이 다루나 |
|---|---|---|
| **내용·상황** — 뭐라고 답할지 | 거절해야 하는데 어떻게 말을 꺼내지, 싸우기 직전에 뭐라고 하지 | 거의 안 다룸 |
| **말투** — 어떻게 들릴지 | 이거 차갑게 보이나, 화난 것처럼 보이나 | 핵심 기능 |
| **실수·격식** — 틀리지 않았는지 | 교수님께 맞춤법·호칭·이모티콘 실수 | 안 다룸 |

확인할 가설:
- H1. 망설임은 주로 **내용·상황** 때문이고, 말투만 따로 걱정하는 경우는 드물다.
- H2. 이미 AI에 묻는 사람이 많고, 안 묻는 이유는 "번거로움"보다 "귀찮음·그 정도는 아님"이다.
- H3. **격식 상황**(교수·선배·알바)에서는 짧은 알림이 실제로 행동을 바꾼다.
- H4. AI에 익숙할수록 AI의 판단을 가볍게 넘긴다("그럼 그렇지").
- H5. 보내는 메시지보다 **받은 메시지 해석**을 더 고민한다.

## 진행 전에

- 대상: 조원 5명 + 가능하면 외부 1~2명. 발표에는 "조원 N명·외부 M명, 탐색용"으로 밝힌다.
- **우리 앱과 위 가설을 먼저 말하지 않는다.** 소개는 마지막 7번에서만 한다.
- **AI 관련 질문은 뒤쪽에서만 한다.** 앞에서 AI 얘기를 꺼내면 답이 AI 쪽으로 쏠린다. 상대가 먼저 말하면 그대로 적는다.
- 대화 원문은 받지 않는다. "어떤 상황이었는지"만 말로 듣는다. 캡처를 보여 주려 하면 정중히 사양한다.
- 녹음하지 않고 메모만 한다. 이름 대신 `P1`, `P2`로 적는다. 나이·성별 같은 신상은 묻지 않는다(5명이면 누군지 드러난다).
- "쓰겠다/안 쓰겠다"보다 **실제로 한 행동, 걸린 시간, 얼마나 자주**를 적는다.
- 상대가 "말투"라고 하면 바로 받아 적지 말고 "말투가 문제였어, 아니면 무슨 말을 할지가 문제였어?"로 한 번 더 확인한다.

시작 멘트 예시:
> 메시지 보낼 때 어떻게 하는지 15분만 물어볼게. 정답은 없고, 최근에 실제로 있었던 일 위주로 얘기해 주면 돼.

## 1. 최근에 망설인 답장 (5분)

1. 최근 한 달 안에 **답장을 보내기 전에 오래 고민한 적**이 있어? 어떤 상황이었어?
   - 누구한테(관계), 무슨 상황(부탁/재촉/거절/사과/싸움 직전/축하·위로/기타)이었는지
2. 그때 제일 고민한 게 뭐였어? (먼저 자유롭게 듣고, 그다음 아래로 확인)
   - "**뭐라고 할지**(무슨 내용을 말할지)"가 고민이었어, "**어떻게 들릴지**(말투)"가 고민이었어, 아니면 "**틀리지 않았는지**(맞춤법·호칭·예의)"였어?
3. 보내기까지 대략 얼마나 걸렸고, 몇 번 고쳤어? 경우의 수(이렇게 말하면 이렇게 나오겠지)를 따져 봤어?
4. 보낸 뒤에 실제로 어떻게 됐어? 걱정한 일이 일어났어?

> 경험이 없다고 하면: "팀플에서 누군가를 재촉하거나 부탁을 거절해야 했던 적", "교수님이나 선배께 연락해야 했던 적"으로 좁혀서 다시 묻는다.

## 2. 그때 한 행동 (3분)

5. 그럴 때 보통 어떻게 해? (혼자 여러 번 고침 / 친구에게 캡처·설명 / AI에 물어봄 / 일단 미룸 / 그냥 보냄 / 기타)
6. 다른 사람이나 AI에게 물어본 적 있으면: 뭐가 도움이 됐고 뭐가 아쉬웠어?
7. **물어볼까 하다가 안 물어본 적**도 있어? 왜 안 물어봤어? (귀찮아서 / 설명하기 번거로워서 / 그 정도 일은 아니라서 / 사적인 내용이라서 / 기타)
8. 이런 고민은 얼마나 자주 해? (거의 매일 / 주 1~2번 / 한 달에 몇 번 / 거의 없음)

## 3. 받은 메시지 해석 (2분)

9. 반대로 **받은 메시지가 무슨 뜻인지** 고민한 적은? ("ㅇㅇ" 이거 화난 건가 같은)
   - 보낼 때 고민이랑 받을 때 고민 중 어느 쪽이 더 잦아?
10. 그럴 때 어떻게 했어? (친구에게 캡처 보내서 물어봄 / AI에 물어봄 / 그냥 넘김 / 직접 물어봄)

## 4. 격식 있는 연락 (2분)

11. 교수님·선배·알바처처럼 **격식 있게 보내야 하는 연락**에서 실수했거나 실수할 뻔한 적 있어? 어떤 실수였어?
    - (맞춤법 / 호칭·존댓말 / 너무 짧거나 캐주얼함 / 시간대 / 내용 빠뜨림 / 기타)
12. 그런 메시지를 보내기 직전에 "이거 한 번 다시 볼래?"라는 알림이 뜨면 어떨 것 같아?

## 5. 알림과 AI 판단에 대한 반응 (2분)

13. 보내기 전에 "이렇게 읽힐 수도 있어"라는 알림이 **도움이 될 것 같은 순간**과 **짜증 날 것 같은 순간**은?
14. AI가 "이 말은 좀 차갑게 들릴 수 있어요"라고 하면 보통 어떻게 받아들여? (따른다 / 참고만 한다 / "그럼 그렇지" 하고 넘긴다 / 기분 나쁘다)
    - 왜 그렇게 받아들이는 것 같아?
15. 일부러 단호하게 쓴 말(거절, 재촉)을 "부드럽게 바꿔 보세요"라고 하면 어떨 것 같아?

## 6. 쓰는 메신저 (1분)

16. 팀플이나 친구 연락은 주로 어디서 해? (메신저 이름만 기록)
17. 그 메신저 안에서 쓸 수 있으면 좋겠어, 아니면 따로 앱을 열어도 괜찮아? 키보드 앱을 바꿔 설치하는 건 어때?

## 7. 마지막에만: 이름 반응 (2분)

18번에서는 후보 이름만 보여 주고, 19번에서 처음으로 기능을 설명한다.

18. 아래 이름만 보고 각각 어떤 기능일 것 같아? 그중 가장 뜻이 분명한 이름은 뭐야?
    - 거울 모드 / 대화 연습 / 상대 입장에서 읽기 / 답장 연습 / 어떻게 들릴까?
19. "내 답장을 받은 상대가 어떻게 받아들일지, 답장 후보 몇 개를 놓고 미리 살펴보는 기능"이야. 언제 써 볼 것 같아? (안 쓸 것 같으면 왜?)

## 8. 배경 (1분, 맨 끝)

답을 해석하기 위한 메모다. 5명으로 집단별 결론은 내지 않는다.

20. 최근 일주일 동안 ChatGPT·Claude 같은 AI를 대략 몇 번 썼어? (안 씀 / 1~2번 / 3~10번 / 거의 매일)
    - 메시지·답장 관련으로 써 본 적 있어?
21. 답장 스타일은 어느 쪽에 가까워? (바로바로 답함 / 생각해 보고 답함 / 상황마다 다름)
22. 격식 있는 연락(교수·선배·알바처·직장)은 얼마나 자주 해? (거의 없음 / 한 달에 몇 번 / 주 1번 이상)

### P0 — 파일럿 응답 (2026-11-10, 팀 내부·질문지 설계용, 집계에서 제외)

팀원이 스스로 답한 것. 질문을 다듬는 데 썼고, 프로젝트를 아는 사람이라 집계에는 넣지 않는다.

- 보내기 전에 망설이는 순간은 꽤 있다. 그런데 "내 말투가 차가워 보이나"가 아니라 **"뭐라고 대답하지"**의 문제다.
- 망설임은 대부분 **상황** 때문이다. 말투 때문에 머뭇거리는 건 싸우기 직전 같은 긴장 상황 정도인데, 그것도 결국 상황 문제다.
- 그럴 때는 LLM에 묻거나 경우의 수를 많이 따져 보고 신중하게 답한다. 안 묻는 건 번거로워서라기보다 귀찮아서다.
- 교수님께 보낼 때 알림이 뜨면 다시 볼 것 같다. 다만 실제로는 **맞춤법 실수** 같은 자잘한 문제가 더 많다.
- AI 판단은 "그럼 그렇지" 하고 넘기는 편이다. AI에 익숙하고, AI가 자주 틀린다는 걸 알아서인 것 같다.
- 배경: AI를 자주 씀, 프로젝트 팀원.

## 정리할 때 볼 것

- **고민 종류 비율**: "내용·상황"이 대부분이면 H1 지지 → 제품을 "말투 알림"에서 "답장 고민 도우미"(맥락 파악 + 후보별 상대 반응)로 재정의하는 근거.
- **안 물어본 이유**: "귀찮음·설명 번거로움"이 많으면 → 맥락을 자동으로 묶어 주는 것이 일반 LLM 대비 차별점 후보. "그 정도 일 아님"이 많으면 → 수요 자체가 약함.
- **받은 메시지 고민이 더 잦으면** → 받는 쪽 해석 도구를 대안으로 검토(상대가 앱을 쓸 필요가 없다).
- **격식 실수 경험이 많으면** → 격식 상황 알림(맞춤법·호칭·캐주얼함)을 따로 검토. 판단이 잘 일치할 가능성이 높아 라벨·평가도 쉬워진다.
- **AI 사용 빈도와 AI 신뢰 반응**을 함께 본다(H4). 5명으로 결론은 내지 않고 경향만 적는다.
- 빈도가 낮거나("거의 없음") 이미 AI로 충분하다는 답이 많으면 → 타깃·상황 수정 또는 보류 검토(로드맵 R-01 마지막 항목). **"수요가 약하다"도 근거가 있으면 정당한 결론이다.**
- "단호함을 지키고 싶다"는 답 → R-02 실패 사례(의도 약화)에 반영.
- 이름 반응 → R-06 이름 후보 결정에 넘긴다.
