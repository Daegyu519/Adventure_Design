# P-14 — 말투 분류기 전문가(KcELECTRA 등) 학습 파이프라인

영역: 엔진·ML (`engine`, 새 폴더 `ml/`). 먼저 읽기: `AGENTS.md`, `CLAUDE.md`, [README 공통 규칙](README.md), `ARCHITECTURE.md`의 전문가·집계 부분, `engine/experts/`(전문가 등록 방식), `engine/harness/providers.py`, `eval/run_eval.py`, `eval/contrast_set.jsonl`, `docs/tasks.md`의 `P-14` 행.
시작: `scripts/claim P-14 <짧은-이름>`. 끝: `P-14` 행을 완료 + `확인:` → `scripts/land P-14` → `AGENTS.md` 갱신 → push.

## 할 일
- 목적: (상대의 마지막 말·최근 맥락, 내 답 초안) → "차갑게 읽힐 확률"을 0.03초 안에 내는 **빠른 실시간 전문가**. 앙상블의 한 표가 된다.
- `ml/`에: 데이터 만들기(아래), 학습(`transformers`, 기본 모델 `beomi/KcELECTRA-base` 또는 `klue/roberta-base`), 평가(대조 세트 정밀도·재현율·지연), 내보내기(ONNX 또는 토치 스크립트).
- **데이터**: AI-Hub "감성 대화 말뭉치"·"공감형 대화"(소유자가 신청 중, 학교 GPU 서버에만 둔다)에서 (감정 섞인 말, 공감 응답)=괜찮음, 같은 말에 짧은 답·무시·화제 전환·이유 없는 거절 등 **차가운 변형**=차가움. 변형은 규칙 + 오픈 모델(라이선스 확인)로 만든다. **Claude·ChatGPT 출력은 약관상 학습 데이터로 쓰지 않는다.** 데이터가 오기 전에는 작은 합성 표본으로 파이프라인이 끝까지 도는지만 확인.
- 엔진 연결: 분류기를 하나의 전문가(예: role tone, 공급자 `classifier`)로 등록하고 `models.yaml`에 **선택(optional) 전문가**로 추가할 수 있게(파일이 없으면 빠짐). 실제 `models.yaml` 반영은 P-12 land 뒤.

## 하지 말 것
- 데이터·가중치·체크포인트를 저장소에 커밋(경로는 README에 적기만), 실제 대화 사용, `eval/contrast_set.jsonl`·T-16 라벨을 학습에 섞기(평가 전용).

## 완료 기준
- `ml/` 스크립트로 합성 표본 학습→평가→내보내기가 한 번에 돈다. 엔진 테스트에서 분류기 전문가가 가짜 모델로 동작(파일 없으면 optional로 빠짐).
- README에 학교 GPU에서의 학습 명령과 데이터 위치.
