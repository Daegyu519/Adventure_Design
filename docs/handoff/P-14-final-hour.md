### A. 구현·학습 설정: 사실과 한계

- **확인된 문제:** 실제 저장 tokenizer는 일반 Fast ByteLevel BPE이고 post_processor가 없다. 기존 경로는 모든 234행에서 CLS/SEP를 삽입하지 않았다. 분류 헤드가 첫 위치를 쓰는데 그 위치는 CLS가 아니라 관계 접두 토큰이었다. 표준 분류 입력 전제가 깨졌지만 이것이 F1=0에 기여한 정도는 아직 모른다. upstream config도 일반 Fast tokenizer를 지정한다([공식 config](https://huggingface.co/beomi/KcELECTRA-base/blob/main/config.json)).
- 새 학습용 `context-pair-v2`에서 CLS/SEP 3개·segment IDs·mask를 명시했다. 기존 v1 기본값과 저장 metadata는 유지했다. 실제 기존 234행 입력 배열이 수정 전과 **완전히 같음**을 확인했다. 기존 모델을 v2로 재해석하지 않았다.
- 클래스 1=cold, 정수 label 전달, softmax 인덱스, attention mask·패딩, 직접 cross-entropy 일치는 정상으로 확인했다. 학습·추론은 같은 encode를 쓴다. 원본 대화·그룹·동일 입력의 분할 누수도 발견하지 못했다.
- 최신 상대 발화가 234/234행에서 중복됐다. 오래된 history는 훈련 151/228행에서 잘렸지만 검증은 0/6행이었다. **마지막 상대 발화와 답장 자체는 검사한 전체 행에서 잘리지 않았다.** 따라서 이 자료에서 최신 발화 손실이 실패 원인이라는 설명은 지지되지 않는다.
- 과거 epoch별 점수는 저장되지 않아 복원할 수 없다. 새 opt-in `--epoch-metrics`로 각 epoch의 양성 예측 수·양 클래스 recall·F1·점수 범위를 기록하도록 했다. tiny fixture 시험은 실제 말투 성능으로 세지 않는다.

## C. 추가 작업 결과

- 원본에서 냉담 관련 어휘를 가진 **미검수 후보 724개(train650/validation74)**를 서버 `private-review-queue/`에 보존했다. 모두 uncertain/pending/is_training_data=false다. 인용·부정·타인의 행동 설명일 수 있어 양성으로 자동 확정하지 않았다. 원문은 GPU 서버에만 있으며 전달 ZIP·Git에는 없다.
- **재학습하지 않았다.** 새로 타당성이 확인된 레이블은 0개, 확대한 독립 검증 그룹도 0개다. 원래 2개보다 충분한 검증 그룹과 다양한 신뢰 가능한 사례라는 조건을 충족하지 않았다. 규칙을 느슨하게 하거나 ChatGPT·Claude 레이블을 넣어 수를 채우지 않았다.
- 구현 수정의 최소 검증으로 generic Fast regression, tiny v2 학습→저장→재로드→TorchScript와 epoch 기록을 시험했다. 새로운 실제 KcELECTRA 성능 결과는 아니다.
- **추가 진단 실험 1회:** 기존 검증 6행·2그룹에서 실제 맥락 / context와 last_them을 모두 제거 / 같은 그룹의 다른 원본 맥락을 비교했다. relation과 답장은 유지했다.
- 맥락 제거 평균 절대 점수 변화 **0.0477**, 교환 변화 **0.0471**, 임계값을 넘나든 행은 둘 다 0개였다. 점수는 맥락에 반응했지만, 감정 맥락을 더 높여야 한다는 약지도 순위는 여전히 0/2였다. 점수 변화는 올바른 맥락 이해의 증거가 아니다.
- 기존 p95 13.80ms는 이전 P100 단일 입력 측정치다. 이번 진단은 CPU로 수행했고 지연을 재측정하지 않았다. v2 모델의 F1·p95는 미측정이다.

## D. 다음 연구 단계

1. 서버 미검수 후보에서 관계·상황·자연스러운 단답·이유 있는 거절을 포함한 작은 표본을 독립 검토한다. coldness와 alert 레이블을 구분하고 애매하면 유보한다. 대량의 수동 검수를 지금 요구하지 않는다.
2. 기존 2개보다 유의미하게 많은 **새 독립 검증 그룹**을 고정한다. 인간 평가 T-16은 학습·생성 규칙 선택·임계값 조정에 섞지 않는다.
3. 입력 v2 수정 효과는 같은 고정 학습 자료·학습 조건으로 먼저 비교하고, 데이터 개선 효과와 섞어 성공 원인을 주장하지 않는다. 이후 모든 epoch에서 양성 예측·recall·F1을 기록한다.
4. 사람 평가·점수 보정·별도 cold 신호 집계 정책이 검증되기 전에는 기존 Gemma3·hint/detail·L3를 변경하거나 경고를 활성화하지 않는다.
