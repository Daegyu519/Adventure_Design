# P-13 — "말투 살펴보기" 버튼과 고쳐 쓰기 3가지

영역: 앱(`apps/mobile`) + 엔진(`engine`). 먼저 읽기: `AGENTS.md`, `CLAUDE.md`, [README 공통 규칙](README.md), `ARCHITECTURE.md`의 상세 경로·고쳐 쓰기 부분, `apps/mobile/components/{Composer,HintBar,DetailSheet}.tsx`, `engine/app/contracts.py`(`DetailIn`/`DetailOut`/`OptionOut`), `engine/pipeline.py`의 `detail`, `engine/prompts/rewrite.md`, `docs/tasks.md`의 `P-13` 행.
시작: `scripts/claim P-13 <짧은-이름>`. 끝: `P-13` 행을 완료 + `확인:` → `scripts/land P-13` → `AGENTS.md` 갱신 → push.

## 할 일
- 지금은 실시간 힌트가 떠야만 상세 시트(이유·고쳐 쓰기)를 열 수 있다. 실시간 힌트가 거의 안 뜨므로 **입력창에 "말투 살펴보기" 버튼**을 두어 힌트가 없어도 `/v1/detail`을 직접 부르게 한다(입력이 비면 비활성, 보내는 중이 아님).
- 상세 결과의 고쳐 쓰기 후보를 **3개**(예: 짧게 / 따뜻하게 / 이유를 덧붙여)로 맞추고, 후보마다 **"보내도 괜찮아요" 또는 "참고" 배지**를 단다. 배지는 엔진이 정한다(예: 후보를 같은 말투 판정에 다시 넣어 낮은 위험이면 "보내도 괜찮아요"). 문구는 템플릿·금지어 검사를 통과한 것만.
- 후보를 누르면 입력창에 넣기(보내지는 않음). 접근성: 버튼·배지에 라벨, 키보드로 고를 수 있게(기존 시트 규칙 따라).
- 계약(`contracts.py`)이 바뀌면 `cd apps/mobile && npm run gen:engine:pull`로 앱 타입을 같은 브랜치에서 다시 만든다.

## 하지 말 것
- `engine/config/models.yaml`의 실시간 전문가·게이트(P-12 진행 중). 고쳐 쓰기 프롬프트를 바꾸면 land 때 평가 게이트가 돈다.
- 전송을 막거나 지연시키는 흐름, 채팅 경로에 엔진 호출 넣기.

## 완료 기준
- 힌트 없이 버튼으로 상세 결과와 후보 3개·배지가 뜬다. 엔진이 꺼져 있으면 버튼은 조용히 실패하고 채팅은 그대로.
- 앱 jest·엔진 pytest에 새 동작 테스트(버튼 활성 조건, 후보 3개, 배지, 금지어, 엔진 실패).

## 확인 방법
`cd engine && uv run pytest -q -W error`, `cd apps/mobile && npm test`, `scripts/check`. 로컬 시연은 엔진을 `FORCE_MOCK=1`로 띄우고 앱 `npx expo start --web`.
