# 단계 1 · 앱 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 파일럿 참가자가 1주 동안 메신저로 쓸 수 있는 Expo 앱(동의 · 로그인 · 초대 · 대화 기본기 · 실시간 힌트 · 살펴보기 · 털어놓기 · 거울 · 리포트 · 설정 · 푸시)을 엔진 mock과 Supabase dev 위에서 만든다.

**Architecture:** `apps/mobile`(expo-router)에서 화면은 `app/`, 재사용 UI는 `components/`, 판단 로직은 RN을 import하지 않는 순수 TS 모듈 `lib/*.ts`로 나누고 순수 모듈만 단위 테스트한다. 채팅은 supabase-js로 DB · Realtime · Storage에 직접 붙고 엔진을 거치지 않는다. 엔진 호출은 `lib/engine.ts` 한 곳이며, `EXPO_PUBLIC_ENGINE_URL`이 비어 있으면 생성 타입에 맞춘 mock을 돌려준다.

**Tech Stack:** Expo SDK(create-expo-app 기본 템플릿 버전) + expo-router + TypeScript strict · `@supabase/supabase-js` · jest-expo · openapi-typescript · `supabase gen types typescript` · expo-image-picker · expo-notifications + expo-device(Android) · Service Worker + Push API(웹) · lucide-react-native · Pretendard

**Spec:** `docs/superpowers/specs/2026-10-27-tone-chat-scope-design.md` (기준 문서 `ARCHITECTURE.md`, `CLAUDE.md`, `docs/tasks.md`를 보완). 단계 0 계획 `docs/superpowers/plans/2026-10-27-phase0-foundation.md`가 끝난 상태(D-01 목업 승인 → T-04 land)에서 시작한다.

**이 계획의 범위:** 앱만. 엔진(`/v1/*`, 웹훅 → 푸시 발송, `mirror_attempts` 기록)과 DB 변경은 엔진 계획의 몫이다. `mirror_attempts`는 엔진이 서비스 권한으로만 쓰고 앱은 쓰지 않는다(읽기는 가능하지만 리포트 숫자는 `/v1/stats/me`로 받는다). 엔진 API는 ARCHITECTURE 4장 그대로라고 가정한다(`/v1/hint`·`/v1/detail`의 `reply_to?` 포함. `/v1/detail` 응답의 `mismatch`는 엔진 T-21이 4장에 더한다). 이 계획이 만드는 새 행은 T-07-live다(Task 4).

**테스트 러너:** jest-expo 하나. Expo 문서의 공식 프리셋이라 babel-preset-expo가 앱과 같은 방식(TS, `@/` 경로)으로 변환하고 RN 모듈 mock이 들어 있다. `node --test`는 import에 `.ts` 확장자를 요구해 Metro · tsc 설정과 어긋난다. 화면은 단위 테스트하지 않고 `npx tsc --noEmit`, `npx expo export --platform web`, 브라우저 확인으로 본다.

- mock은 `lib/engineMock.ts` 한 곳. 응답은 `satisfies <생성 타입>`으로 써서 계약이 바뀌면 tsc가 잡는다.

## Global Constraints

- 루트 체크아웃(`~/Projects/tone-chat`, `main`)에서 직접 고치지 않는다. 작업은 `scripts/claim`이 만든 worktree에서 하고 `scripts/land`로 합친다.
- 앱에는 모델 키와 Supabase service role 키를 넣지 않는다. 앱 환경 변수는 `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY`, `EXPO_PUBLIC_ENGINE_URL`, `EXPO_PUBLIC_VAPID_PUBLIC_KEY`뿐이다. `process.env.EXPO_PUBLIC_*`는 구조 분해 없이 그대로 써야 번들에 들어간다.
- 환경 변수 파일: 앱 키(`EXPO_PUBLIC_*`)는 `~/Projects/tone-chat/apps/mobile/.env`에, 엔진 키(`SUPABASE_*`, `NVIDIA_API_KEY` 등)는 루트 `.env`에 둔다(Expo는 앱 폴더의 `.env`만 읽는다). `scripts/claim`이 두 파일을 worktree의 같은 위치로 자동으로 심볼릭 링크하므로 따로 `ln`을 하지 않는다(파일이 원본에 있을 때만 걸린다. 복사하지 않는다). worktree를 잡은 뒤에 키 파일을 만들었다면 그 worktree에서 손으로 건다: `ln -s ~/Projects/tone-chat/.env .env`, `ln -s ~/Projects/tone-chat/apps/mobile/.env apps/mobile/.env`. 키는 사용자가 넣는다(T-02). 키가 없으면 그 확인은 "T-02 대기"로 tasks.md 확인 줄에 적고 넘어간다. 단 tasks.md 선행 칸에 T-02가 있는 행(T-07)은 `scripts/land`가 `완료`만 받으므로 "mock/로컬 기준"으로 줄여 `완료`로 하고, 실제 확인은 `T-07-live` 행으로 남긴다(Task 4).
- 엔진 선행 작업(T-14, T-21, T-24, T-35, stats)은 기다리지 않는다. mock으로 만들고, 엔진이 land된 뒤 각 작업의 "엔진 연결 확인"을 한다. 엔진은 `CORS_ORIGINS`(기본 `http://localhost:8081`)로 웹 origin을 허용한다(엔진 T-14). 브라우저에서 사전 요청이 막히면 엔진 쪽 문제로 `.coord/log.md`에 남긴다. 엔진은 로컬에서 기본 포트 8000으로 뜬다.
- 채팅 경로(보내기 · 받기 · 목록)에 엔진 호출을 넣지 않는다. 힌트 · 살펴보기는 전송을 막거나 늦추지 않는다(보내기 함수는 엔진 결과를 await하지 않는다).
- 사진은 엔진에 보내지 않는다. 하소연 원문은 앱에서도 저장 · 로그하지 않는다(`console.*`, AsyncStorage 금지).
- 엔진 · DB 타입은 생성 파일만 쓴다. 손으로 복제하지 않는다(위 seed 예외만).
- 색은 `useTheme().colors`에서만. 코드에 색 리터럴(`'#…'`, `rgb(`) 금지 — Task 1이 `scripts/check`에 grep으로 건다. 반투명 배경은 `colors.text` + `opacity`.
- 노란색 · 갈색 금지, 말풍선 꼬리 없음, 모서리 `radius.bubble`(18). 카카오톡 · 인스타그램 · 디스코드의 이름 · 로고 · 색 · 에셋 금지. `design-system/tone-chat/MASTER.md`를 따른다.
- 글자는 `AppText`(Task 2)로만: Pretendard, 본문 `font.body`(16), 줄 간격 `font.body * font.lineHeight`(24).
- 아이콘은 Lucide. 이모지를 아이콘으로 쓰지 않는다(공감 이모지 6개만 내용이라 예외).
- 움직임 150~250ms(`MOTION_MS = 200`), 시스템 '동작 줄이기'면 움직임 없음(`useReducedMotion`). 힌트 · 살펴보기에 진동(`Vibration`, `expo-haptics`) 없음.
- 누르는 것은 모두 44pt 이상(`minHeight: 44, minWidth: 44` 또는 `hitSlop`), `accessibilityRole`과 한국어 `accessibilityLabel`을 단다. 대비 4.5:1은 토큰이 보장한다.
- 사용자 문구는 한국어, "~일 수도 있어요". 사람을 평가하는 말 금지. 점수는 "차이"로만. 거울에 폭죽 · 연속 출석 · 효과음 없음.
- 읽힘 키는 `차갑게, 성의없게, 화나게, 무난하게, 따뜻하게` 다섯 개, 단계는 `자주 / 가끔 / 드물어요` 세 개. 그룹은 최대 8명. 메시지 수정 · 삭제 없음.
- 8GB 맥: `npx expo export`·`npx expo start`는 맥 전체에서 한 번에 하나. 시작 전 `mkdir ~/Projects/tone-chat/.coord/expo.lock`(실패하면 기다림), 끝나면 `rmdir`. jest는 `--maxWorkers=2`.
- 서브에이전트 모델은 `sonnet` 또는 `opus`만. 각 작업의 권장 모델을 따른다.

| 경로 | 요청 | 200(feedback은 202) 응답 |
|---|---|---|
| POST `/v1/hint` | `room_id`(uuid), `text`(1~500), `seq`(int), `reply_to?`(int64, 다른 방 메시지면 422) | `seq`, `hint: {title, detail} \| null`, `trace_id` |
| POST `/v1/detail` | `room_id`, `text`, `intent?`(enum `단호하게·미안하게·가볍게`), `reply_to?` | `alert`(bool), `top_reading`(읽힘 enum), `readings`(다섯 키 모두 필수, 값 enum `자주·가끔·드물어요`), `why: string[]`, `options: {label, text, keep, change}[]`, `mismatch?: string \| null`(엔진이 만든 "보내려던 뜻과 어긋남" 한 줄. 앱은 그대로 보인다), `footnote`, `trace_id` |
| POST `/v1/feedback` | `room_id`, `message_id`(int64), `text`(1~1000) | `ack` |
