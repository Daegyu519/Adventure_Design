### 3. 모델 성능을 올리려면? → 잴 방법이 없다

- 지금까지 실제 평가는 16문장. 오차가 ±20%p라 "좋아졌다"를 말할 수 없다. `baseline.json`은 mock이라 실제 품질과 무관.
- 그래서 **라벨(T-16)이 먼저**. 그런데 질문: 라벨이 객관적 정답인가?
  - 아니다. **"이 사람들(대학생)의 합의된 판단"**이다. 그래서 "정확도"보다 **"사람 판단과의 일치도"**라고 부른다.
  - 사람끼리의 일치도(kappa)가 모델에 기대할 수 있는 **천장**이다.
  - 갈린 사례는 버리지 않고 "판단 어려움" 구간으로 쓴다(모델이 단정하면 안 되는 곳).
- 조원 **5명**이 라벨한다. 평가에는 사람 수보다 문장 수가 효과가 크다(60문장 ±11%p, 200문장 ±6%p). 1차 60문장은 5명 전원, 2차로 팀플 상황 40~60쌍을 3명씩 추가하는 안.
- 개선 방법은 싼 순서로: ① 기준값·가중치 조정 → ② 프롬프트(틀린 사례 분류 → 가설 하나 → 한 가지 수정 → 평가용 세트로 재측정) → ③ 모델 구성. KcELECTRA 재학습은 2주 안에 무리.
- 조정용과 평가용을 나눈다(같은 문장으로 조정·평가하면 숫자가 부푼다).

### 4. 본질 질문: 이게 쓸모가 있나?

사용자 생각: "차가움을 느끼는 건 사람·상황마다 천차만별이다. 이건 정확한 검증이 아니라 **제동을 걸어 주는 보조 수단**이다. 보류하면 맥락을 묶어 LLM에 넘기는 게 낫지 않나?"

- **판정기 → 제동 장치**로 보면, 사람마다 다르다는 사실이 오히려 "어디서 브레이크를 밟을지"의 근거가 된다(다수가 멈칫하는 곳만 알림, 갈리는 곳은 사용자에게 맡김).
- LLM으로 넘기기: 깊은 분석은 범용 LLM이 낫다. 다만 "그럼 ChatGPT 쓰면 되잖아"에 답하려면 우리 가치는 **타이밍**(문제 될 순간에만)과 **맥락 묶기**(복사 없이 한 번에)여야 한다. 외부로 보낼 때 이름·개인정보 가리기와 동의(규칙 16) 필요.

당위성 문제를 냉정하게 정리했다:

| 문제 | 치명도 |
|---|---|
| ① 문제가 자주·아프게 있나 | 치명적 |
| ② 필요한 사람이 안 씀(걱정 많은 사람은 이미 고침, 차가운 사람은 자각 없음) | 치명적 |
| ③ 사후 수습이 사전 검사보다 쌈, 이미 LLM·친구에 물음 | 큼 |
| ⑥ 새 메신저·키보드 설치 장벽, 대기업 기본 기능과 경쟁 | 큼 |
| ④ 차가움이 나쁜가(단호함의 가치) ⑤ 정답 없음→신뢰 ⑨ 받는 쪽 상태를 못 봄 | 중간 |
| ⑦ 하소연 기능의 감시감 ⑧ 효과 증명 어려움 | 중간 |

①②는 코드로 해결되지 않고 **사람을 관찰해야만** 알 수 있다. 지금까지 이것 없이 만들기만 한 것이 근본 문제.

발산한 대안: A 받는 쪽 해석 도구("이거 화난 거야?") · B 연습·교육(사회 초년생, 한국어 학습자) · C 팀플 조율 · D 사후 회복 · E 내 말투 리포트 · F 연구로 전환("수요가 약하다"도 근거 있으면 정당한 결론).

### 5. 사용자 자기 응답 (P0) → 문제 재정의

- 망설이는 순간은 꽤 있다. 그런데 **"뭐라고 대답하지"의 문제지, 말투 문제가 아니다.** 망설임은 상황 때문이고, 말투로 머뭇거리는 건 싸우기 직전 정도.
- 그럴 땐 LLM에 묻거나 경우의 수를 따진다. 안 묻는 건 번거로워서가 아니라 귀찮아서.
- 교수님께 보낼 때 알림은 효과 있을 듯. 실제로는 맞춤법 실수가 더 잦다.
- AI 판단은 "그럼 그렇지" 하고 넘긴다(AI 익숙, 오탐 경험).

해석:
- 우리는 진짜 고민("뭐라고 답하지")의 일부(말투)만 붙잡고 있었다.
- 그래도 엔진 재사용 여지가 있다: 상세 경로의 맥락 전문가가 이미 **상대 상태·상대가 기대하는 것**(`expectation_points`)을 뽑고, 거울은 **상대가 어떻게 받아들일지**를 시뮬레이션한다 → "상대 기대 → 답장 후보 → 후보별 반응" = 사람이 머릿속으로 하는 경우의 수.
- **격식 상황**(교수·선배)은 판단이 잘 일치하고 맞춤법·호칭처럼 객관적 확인거리가 있어 "정답 없음" 문제가 약하다.
- 단, P0는 한 명이고 AI에 익숙한 팀원이라 집계에서 뺀다.

### 6. 인터뷰 재설계

- 고민을 **내용·상황 / 말투 / 실수·격식** 세 종류로 나눠 묻는다. 가설 H1~H5.
- 배경 정보(AI 사용 빈도, 답장 스타일, 격식 연락 빈도, 팀플 여부)는 **맨 끝**에 묻는다(앞에서 AI 얘기를 하면 답이 쏠림). 나이·성별은 묻지 않는다(5명이면 누군지 드러남). 5명으로 집단별 결론은 내지 않는다.
- 마지막에 콘셉트 시안 3개(A 말투 알림 / B 답장 고민 도우미 / C 격식 체크)를 팀플·교수님 두 상황으로 보여 주고 고르게 한다.
- 순서: **인터뷰 먼저, 라벨링 나중**(라벨 양식이 "말투" 쪽으로 생각을 쏠리게 하므로).
