## 1. 원칙

1. **조용하게, 판단하지 않게.** 힌트는 보내는 사람에게만, 한 줄로, 확정하지 않는 말로 뜬다. 경고·오류처럼 보이지 않는다.
2. **전송을 막지 않는다.** 힌트가 있어도 전송 버튼은 그대로다. 모달로 가로막지 않는다.
3. **출처를 짐작하게 하지 않는다.** 누가 불편해했는지, 누가 털어놓았는지 드러내는 문구·숫자·표시를 쓰지 않는다.
4. **점수가 아니라 차이.** 거울·리포트는 등급·순위·잘함/못함 색을 쓰지 않는다. "예측과 한 칸 차이"처럼 차이로만 말한다.
5. **다른 메신저처럼 보이지 않는다.** 카카오톡·인스타그램·디스코드의 이름·로고·색·에셋을 쓰지 않는다(노란색·갈색, 하늘회색 대화 배경 포함). 말풍선 꼬리는 묶음의 마지막 말풍선에만(아이메시지식).

## 2. 색

**모노(애플 미니멀)**: 주색은 거의 검정(다크는 거의 흰색), 회색은 iOS 시스템 회색. 힌트용 따뜻한 색(라이트는 앰버·주황, 다크는 크림), 거울용 라벤더는 그대로. 빨강(`danger`)은 오류·로그아웃에만 쓴다.

- **보정 (P-26)**: 시안의 라이트 `danger` `#FF3B30`은 흰 바탕 대비 3.55라 4.5:1에 못 미쳐, 같은 계열에서 대비만 올린 `#D70015`(5.3)로 바꿨다. 기준(4.5:1)은 그대로.
- 묶음 목록(설정)은 `useTheme().grouped`: 라이트는 화면 `surface` + 칸 `background`, 다크는 화면 `background` + 칸 `surface`.

- **대비 (검사 대상, 두 모드 모두 4.5:1 이상)**: text/background, textMuted/background, onPrimary/primary, onBubbleOther/bubbleOther, hintText/hintBg, onMirror/mirror, danger/background. 모노 값은 `danger` 라이트 1건 외 모두 통과했다.
- **노란·갈색 금지 (검사)**: HSL 색상각 20°~65°(갈색~노랑)이면서 채도 > 0.5, 명도 < 0.9인 색은 쓰지 않는다. 명도 0.9 이상인 아주 옅은 색만 예외. 라이트 힌트 글자 `#9A3412`는 색상각 15°라 범위 밖이다.
- **보정 1건**: 다크 `hintText`는 스펙 시작 값 `#FDBA74`(색상각 31°, 채도 0.97, 명도 0.72)가 갈색 범위에 걸려, 색상각·채도는 두고 명도만 0.90으로 올려 `#FEE7CF`로 바꿨다(hintBg 위 대비 13.6). **다크 모드 힌트는 크림 글자 #FEE7CF + 어두운 웜 배경 #2A1E12, 사용자 승인 2026-10-27.** 다크에서는 점도 크림색이라 앰버로 부르지 않는다.
- **테두리**: iOS식이라 입력창(메시지 입력)은 `border` 1px, 구분선은 머리카락 두께(`StyleSheet.hairlineWidth`) `border`. 가장자리가 보여야 쓸 수 있는 큰 입력 상자(털어놓기 등)는 `textMuted` 테두리를 그대로 쓴다.
- **파생 색은 하나만**: 시트 뒤 가림막 `--scrim` = 라이트 `color-mix(text 32%, transparent)`, 다크 `color-mix(background 72%, transparent)`. 그 밖에 토큰에 없는 색을 만들지 않는다. 그림자도 쓰지 않고 `border`로 층을 나눈다.
- 다크 모드는 시스템 설정을 따르고 설정 화면에서 바꿀 수 있다.

## 5. 컴포넌트

### 말풍선 (메신저식 배치, P-26)
- 묶음 = 같은 사람·같은 날의 연속 말풍선(`lib/thread.ts`의 `slotFor`). 묶음 사이 8, 안 3.
- **받은 것**: 묶음의 **첫** 말풍선에만 둥근 아바타(38, 이름 첫 글자, `bubbleOther` 바탕)와 이름(12~13, 500, `textMuted`)이 붙는다. 이어지는 말풍선은 아바타 칸(38+8)만큼 들여쓴다. 1:1에서도 같다.
- **내 것**: 오른쪽, `primary` / `onPrimary`. 받은 것은 왼쪽 `bubbleOther` / `onBubbleOther`. 최대 너비 85%(열 기준).
- **모서리·꼬리**: 네 모서리 18, **묶음의 마지막 말풍선만** 아래 모서리 하나를 6(받은 것 왼쪽 아래, 내 것 오른쪽 아래). 아이메시지식이고 삼각형 꼬리는 그리지 않는다.
- **시간**: 같은 사람·같은 **분** 묶음의 마지막 말풍선 옆에만(11, `textMuted`). 내 것은 말풍선 왼쪽, 받은 것은 오른쪽.
- **안 읽은 수**: 내 말풍선 옆(11.5, 700, `primary`). 모두 읽으면 지운다(시간과 같은 자리, 시간 위).
- **날짜 구분**: 날이 바뀌는 첫 메시지 위 가운데 알약 "2026년 11월 1일 일요일"(12, 500, `textMuted`, `surface` 바탕).
- 접근성: 이름은 말풍선 접근성 이름("보낸 사람, 글, 시각, 안 읽은 수")에 매번 들어 있다. 아바타·시간·수 글자는 화면 읽기에서 숨긴다.
- 눌림: 누르는 순간(pointer-down) 투명도 0.85. 메뉴 "⋯"는 키보드 포커스가 올 때만 보인다(탭 순서·접근성 이름은 그대로, 터치·마우스는 말풍선 자체로 연다).
- 답장 인용: 말풍선 안 위쪽, 왼쪽 2px 선 + 원문 보낸 사람·첫 줄(13). 탭하면 원문으로 이동.
- 공감: 말풍선 아래 알약 칩(이모지 + 수, 13). 고정 6개, 한 사람 하나.
- 입력 중: 받은 말풍선 자리에 점 3개(`textMuted`). 스크린리더용 "○○ 님이 입력 중이에요".
- 받은 메시지에만 "털어놓기"(메뉴 안). 내 메시지에는 없다.

### 화면 구조 (애플식)
- **큰 제목**: 탭 화면(대화·거울·리포트·설정)은 `large`(34/700)로 시작.
- **위 막대(대화방)**: 가운데 제목(17/600) + 부제("1:1"·"N명", 12, `textMuted`), 왼쪽 "‹ 대화"(`primary`, 접근성 이름 "뒤로"), 오른쪽 "⋯"(방 정보). `bar` 바탕 + 머리카락 선.
- **대화 목록 줄**: 아바타 52, 이름 17/600 + 시각 14, 미리보기 15 + 안 읽은 수 배지(22, `primary`). 줄 사이 머리카락 선은 아바타 오른쪽부터.
- **묶음 목록(설정)**: 작은 라벨(13) 아래 둥근(12) 칸. 스위치 줄 최소 높이 48, 모양 선택은 iOS 분할 조절기(`border` 바탕 위 흰 칸). 로그아웃은 칸 안 가운데 `danger` 글자.
- **탭 바**: 불투명 `bar` + 머리카락 위 선. 반투명(`position: absolute`)은 쓰지 않는다(아이폰 웹 안전 영역이 깨진다, P-22). 웹 CSS 높이 `calc(62px + env(safe-area-inset-bottom))`, paddingTop 4, 이름 줄 16 유지.
- **입력줄(iOS)**: 왼쪽 둥근 + (사진, 34 동그라미 안에 아이콘, 눌림 44), 둥근 입력창(18, 최소 36, `background` 바탕, `border` 테두리), 오른쪽 둥근 보내기(34, `primary`). 바탕 `surface` + 머리카락 위 선.

### 힌트 (입력창 위 한 줄)
- 모양: 입력창 바로 위 한 줄, 모서리 14, `hintBg` 바탕. 왼쪽부터 **점**(8px, `hintText`. 라이트는 주황, 다크는 크림) · 제목 "차갑게 느껴질 수도 있어요"(14.5) · "살펴보기 ›"(13, 600) · 닫기(X). 글자는 모두 `hintText`.
- 한 번에 하나만. 제목은 템플릿 세 개 중 하나("차갑게 / 성의 없게 / 화난 것처럼 느껴질 수도 있어요").
- 전송 버튼 모양·동작은 바뀌지 않는다. 힌트가 떠 있어도 바로 보낼 수 있다.
- 빨강·경고 아이콘·진동을 쓰지 않는다.
- 움직임: 나타날 때 아래 8px에서 올라오며 투명 → 불투명, 200ms ease-out. 사라질 때 150ms 투명. 동작 줄이기가 켜져 있으면 이동 없이 투명도만 바꾼다.

### 살펴보기 시트
- 아래에서 올라오는 시트, 위 모서리 20, 손잡이, 제목 "살펴보기" + 닫기.
- 순서: 보낼 문장 → **의도 칩** "단호하게 / 미안하게 / 가볍게"(고르지 않아도 됨, 선택 시 `primary` 바탕) → **이렇게 읽힐 수 있어요**(세 칸 격자, 칸마다 읽힘 이름 · 점 3개 · "자주 / 가끔 / 드물어요" 단계 글자를 위아래로, 단계 글자는 줄 안에서 끊지 않음, 퍼센트 금지) → **이유** 두 줄 → **후보 A/B**(라디오 카드, 원문과 달라진 어절만 `primary` 글자 + 밑줄) → 각주 → 버튼 "그대로 보낼게요"(보조) · "입력창에 적용"(주).
- 어긋남 한 줄은 의도와 가장 많이 읽힌 뜻이 어긋날 때만(스펙 5장 표).
- 각주: "비슷한 대화에서 모인 반응을 바탕으로 한 조언이라 틀릴 수도 있어요. 누가 어떤 반응을 남겼는지는 알 수 없어요."

### 털어놓기 시트
- 받은 메시지 인용(보낸 사람·시간·문장) → 여러 줄 입력(1~1000자, 글자 수) → 안내 상자(`surface`) → 주 버튼 "털어놓기".
- 안내: 적은 글은 저장되지 않고 상대에게 전달되지 않는다는 것, 누가 남겼는지 드러나지 않게 조심스럽게 반영될 수 있다는 것. 무엇이 추출됐는지는 보여 주지 않는다.

### 거울 카드
- 카드(모서리 16, `surface`, `border`). 위에 종류 칩(`mirror` / `onMirror`): 역할극 · 되돌려 받기 · 예측 맞히기. 진행 점 3개.
- 1~5칸 선택: 44px 이상 칸 다섯 개(라디오), 양끝 설명 "덜 부정적 / 많이 부정적". 고른 칸은 `mirror` 바탕.
- 결과: "예측과 한 칸 차이"(20, `mirror`) + 문장에 대한 한두 줄. 사람을 평가하지 않는다.

### 리포트
- 숫자 세 개(예측 차이 · 이번 주 힌트 · 스스로 고친 비율) + 주별 힌트 수 막대.
- 막대 하나의 색(`primary`가 이번 주, 지난 주들은 `textMuted`), 위 모서리 4px, 막대 사이 간격, 값은 글자색 토큰. 순위·등급·빨강/초록 판정 금지.

### 버튼 · 칩 · 입력
- 주 버튼: `primary` 바탕, `onPrimary` 글자, 높이 48, 모서리 999, 16/600.
- 보조 버튼: `surface` 바탕, `border` 테두리, `text` 글자.
- 아이콘 버튼: 44×44, `aria-label` 필수.
- 칩: 높이 44(터치 영역), 모서리 999. 선택은 `primary` 바탕 + `aria-pressed`.
- 메시지 입력창: `background` 바탕, `border` 테두리 1px, 모서리 18, 글자 16(위 "입력줄"). 여러 줄 입력 상자(털어놓기)는 모서리 16, `textMuted` 테두리.
- 탭바: 대화 · 거울 · 리포트 · 설정. 활성 `primary`, 나머지 `textMuted`. 아이콘 + 글자(11, 500).

## 6. 움직임

- 150~250ms, `ease-out`(들어올 때)·`ease-in`(나갈 때). `transform`·`opacity`만 움직인다.
- 시트: 아래에서 올라옴 250ms(튕김 없는 스프링, damping 1.0 느낌의 ease-out). 힌트: 위 5장 규칙.
- **눌림 반응은 누르는 순간(pointer-down)** 에 바로 보인다(투명도 0.5~0.85, 크기 변화 없음). 놓은 뒤에 반응하지 않는다.
- **동작 줄이기**(`prefers-reduced-motion` / RN `AccessibilityInfo.isReduceMotionEnabled`)를 따른다: 이동을 빼고 투명도만.
- 진동 없음(힌트·시트 모두). 애니메이션 라이브러리는 RN 기본 `Animated` 또는 Reanimated. GSAP 쓰지 않는다.

## 7. 문구

- 한국어, 확정하지 않는 말투: "~일 수도 있어요", "~하기도 해요", "~일 수 있어요".
- 금지어(엔진 검사와 같음): 확실히, 분명히, 반드시, 상대가 말하길, 상대방이 그러는데, 님이 말한, 피드백을 남겼, 싫어했어요, 기분 나빠했어요.
- 사람이 아니라 문장을 말한다("이 문장은 ~처럼 읽힐 수도 있어요").
- 버튼은 사용자의 말로: "그대로 보낼게요", "입력창에 적용", "털어놓기".

## 8. 접근성

- 대비 4.5:1 이상(`check_contrast.py`), 터치 영역 44pt 이상, 아이콘만 있는 버튼은 스크린리더 라벨.
- 키보드·스위치 포커스가 보이게(`primary` 2px 테두리).
- 색만으로 뜻을 전하지 않는다: 힌트는 글자, 읽힘은 단계 글자, 선택은 `aria-pressed`/`aria-checked`.
- 글자 크기 키움(Dynamic Type)에서 힌트 줄은 두 줄까지 늘어나도 된다.

## 9. 금지

- 노란색·갈색 계열, 하늘회색 대화 배경, 묶음 중간 말풍선의 꼬리, 그라데이션 말풍선, 다른 메신저의 색·아이콘·이름.
- 힌트에 빨강·경고 삼각형·진동·모달.
- 점수·등급·순위·잘함/못함 색.
- 이모지 아이콘, 초대형 글자, 화려한 장식, 그림자 겹치기.
- 레이아웃이 밀리는 hover(scale), 전환 없이 툭 바뀌는 상태 변화(150~250ms 전환을 쓴다. 동작 줄이기에서는 예외), 보이지 않는 포커스.

### 도구 원본 추천에서 버린 것

ui-ux-pro-max가 낸 원본에서 다음을 버렸다. 색(Messenger blue `#2563EB` + 초록 CTA)은 차분한 틸·따뜻한 힌트색·라벤더로 바꿨다 — 파랑+초록은 기존 메신저 느낌이 강하고, 힌트·거울처럼 역할마다 색을 따로 둬야 해서다. 글꼴 Lora/Raleway는 한글이 없어 Pretendard로 바꿨다. 스타일 "Exaggerated Minimalism"(초대형 900 글자, 큰 여백)은 패션·포트폴리오용이라 조용한 채팅과 맞지 않아 뺐다. 페이지 패턴 "App Store Style Landing"(별점·다운로드 버튼)은 랜딩 페이지용이라 앱 화면과 관계가 없어 뺐다. 움직임 예시의 GSAP 코드는 React Native에서 쓰지 않으므로 빼고 시간(150~250ms)과 동작 줄이기 규칙만 남겼다. hover 들어 올리기·카드 그림자·`cursor:pointer` 같은 웹 전용 규칙은 터치 앱이라 뺐다(목업 HTML에서만 씀). 남긴 것은 범주 판단(미니멀 + 작은 상호작용, 보낸/받은 말풍선 대비, 입력 중 회색), 대비 4.5:1, 이모지 아이콘 금지, 보이는 포커스, 동작 줄이기 체크리스트다.
